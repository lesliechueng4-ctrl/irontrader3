# 消息面刺激 · 权重设计（v1 观察模式）

> 代码：`news_catalyst.py`（抓取、分类、打分）、`news_routes.py`（接口）
> 界面：作战大屏「重大消息雷达」、单票研报「消息面」卡片、作战台候选上的消息角标
> 测试：`tests/unit/test_news_catalyst.py`

## 1. 目标和原则

- **不错过重大消息**：重组、控制权变更、立案调查、退市风险、业绩大变脸这类消息，第一时间在大屏上看到；
  命中自选股或今日候选的要置顶。
- **可解释**：每条消息的方向、等级、衰减和对总分的贡献都显示出来，分数怎么来的一眼能看懂。
- **先观察，再接入**：v1 不改变龙头、低吸、执行闸的任何结论。先看一段时间、调好权重，再决定接进哪里（见第 6 节）。
- **不编造**：数据源失败时显示"暂不可用"；标题看不出方向的（例如只写"业绩预告"）标成"看正文"，不去猜。

## 2. 数据源

| 来源 | 接口 | 可信度 | 说明 |
|---|---|---|---|
| 公告 | 东方财富公告中心 `np-anotice-stock.eastmoney.com` | 最高（上市公司正式披露） | 带分类标签和发布时间；支持按日期、按多只股票查询 |
| 公告兜底 | 巨潮资讯 `cninfo.com.cn` | 最高（证监会指定披露平台） | 东财失败时自动切换，只有日期、没有分类标签 |
| 新闻 | 东方财富资讯搜索 `search-api-web.eastmoney.com` | 中（媒体转述，常重复、常滞后） | 只收**标题开头 8 个字以内出现股票名称**的稿件，避免"遭宁德时代减持，湖南裕能……"这种被错记到宁德时代头上 |

全市场雷达每 10 分钟重扫一次（多人共享缓存）。首次构建要翻 10–30 页公告，约 20–40 秒。

## 3. 打分公式

每条消息：

```
贡献 = 方向 × 等级分 × 来源权重 × 时间衰减
时间衰减 = 0.5 ^ (已过交易日 / 半衰期)
```

汇总成一只股票的消息面分数：

```
同一类型的多条消息：最强的一条 + 其余每条的 25%     （媒体转载同一公告不会重复计分）
消息面分数 = 100 × tanh(各类型合计 / 50)             （落在 -100 ~ +100，越极端越难再加分）
```

### 可调参数（都在 `news_catalyst.py` 顶部）

| 参数 | 当前值 | 含义 | 调大会怎样 |
|---|---|---|---|
| `LEVEL_POINTS` | 重大 40 / 显著 20 / 一般 8 / 噪音 0 | 事件等级的基础分 | 该等级的消息更容易主导总分 |
| `SOURCE_WEIGHT` | 公告 1.0 / 新闻 0.5 | 来源可信度 | 新闻调高会让媒体炒作更有分量 |
| 半衰期（每条规则） | 1–10 个交易日 | 影响持续多久 | 越长，旧消息越久还在算分 |
| `SAME_TYPE_EXTRA` | 0.25 | 同类第 2 条起的折扣 | 调高会让"连续发同类公告"叠加得更多 |
| `SCORE_SCALE` | 50 | tanh 缩放 | 调小会让分数更快顶到 ±100 |
| `ACTIVE_DECAY` | 0.25 | 衰减到这之下就不再算"重大提醒" | 调低会让重大提醒挂得更久 |

**参考数值**：一条今天首次反应的重大利空公告 → 贡献 -40 → 消息面 **-66**；两条不同类型的重大利空 → 约 **-92**；
一条显著利好（如中标） → **+38**；只有一条媒体报道的中标 → **+20**。

### 时间怎么算

- **反应日**：公告的 `notice_date` 就是它第一个能被交易的日子；收盘（15:00）后发布的记到下一天。
- **长假**：国庆期间发布的公告，反应日落在节后首个交易日。在那之前显示"待首次交易"，衰减不开始。
- **只数交易日**：周末和节假日不算衰减（交易日历来自 AKShare，取不到时按工作日算）。

### 各类事件的默认设定（节选，全表见 `RULES`）

| 方向 | 等级 | 事件 | 半衰期（交易日） |
|---|---|---|---|
| 利空 | 重大 | 立案调查 / 强制措施、退市风险、戴帽 ST | 10 |
| 利空 | 重大 | 债务违约 / 资金占用 | 5 |
| 利空 | 显著 | 行政处罚、业绩预减/亏损、股东减持计划、股份冻结/司法拍卖、终止重组 | 3–5 |
| 利空 | 一般 | 解禁、问询函、异常波动、诉讼、董事长离任、减持进展 | 1–2 |
| 利好 | 重大 | 重大资产重组（只认预案 / 草案 / 审核通过等主文件）、控制权变更、筹划重大事项停牌、摘帽 | 5 |
| 利好 | 显著 | 业绩预增/扭亏、中标/重大合同、产品获批 | 2–3 |
| 利好 | 一般 | 增持、回购、股权激励、转增、定增获批、政府补助、终止减持 | 1–2 |
| 看正文 | 显著/重大 | 只写"业绩预告"、破产重整/预重整、复牌 | 1–5 |

两条通用修正：

- **后续进展降级**：标题里有"进展 / 第 N 次风险提示 / 持续"的，一律降为"一般"。
  事件早已公布，只是例行提醒（例如 ST 公司每月发一次的"风险警示相关事项进展"），不能再当成重大新消息。
- **程序性文件不算**：一次重组会配套几十份文件（法律意见书、财务顾问报告、"符合 xx 规定的说明"……），
  只认主文件；雷达里同一公司同一件事的多份文件合并成一条，并显示"同事件另有 N 份文件"。

## 4. 已知局限（v1）

1. **只看标题**：规则是关键词正则，会有误判。例如"关于本次重大资产重组的一般风险提示"，实际可能是**出售**资产，却被判成利好。
   调规则时优先看雷达里的误判，把排除词加进对应规则的 `exclude`。
2. **方向需要正文的**（业绩预告、重整）只提醒去看，不计分。
3. **没有"利好兑现"判断**：消息出来前股价已经连板，公告本身可能就是出货信号。v1 没有结合价格。
4. **没有政策面 / 板块级消息**：只看个股公告和新闻，没有接 7×24 快讯、部委政策。
5. **新闻源**：东财资讯搜索会对部分请求返回一份与请求无关的默认结果。代码能识别这种情况，并显示为"新闻暂不可用"，不会误用。
   在开发环境里，这个问题每次都会出现；你电脑上的情况还没确认，请看研报「消息面」卡片里新闻是否显示"N 条"。

## 5. 界面上看到什么

- **作战大屏 · 重大消息雷达**
  - 顶部统计：重大利好、重大利空、显著事件各有几条。
  - 列表：命中自选或今日候选的置顶，并高亮；可以按"关注 / 利好 / 利空"筛选。
  - 点股票名进入单票研报，点标题打开公告原文。
- **作战台候选**：如果某只候选被雷达命中，卡片下方多一行消息提示。候选排序不变。
- **单票研报**
  - 统一结论下方出现"消息面提醒"，但只在有重大消息时出现，并注明这些消息没有计入结论。
  - 下面是「消息面」卡片：左侧是分数；中间是主要来源、重大提醒、需要看正文的项目；最后是逐条明细（贡献、衰减、半衰期）。
  - 常规信息（股东大会、董事会决议等）默认隐藏，可以用开关打开。

## 6. 接入原系统的方案（待作者选择）

v1 只观察。观察一两周、调好规则后，可以按下面的顺序逐级接入。每一级都是独立的开关，可以只选其中几个。

### A. 维持观察（现状）
- 做法：只展示、只提醒。
- 优点：不会因为规则误判而错过或误杀机会。
- 代价：重大利空要靠自己看见，系统不会拦住你。

### B. 重大利空一票否决（建议第一个接入）
- 做法：当前有效的**重大利空**（立案、退市风险、戴帽、债务违约）出现时：
  - 统一结论降为"仅观察"，`key_reason` 写"重大利空：立案调查（今日首日）"；
  - 作战台候选降到观察池。
- 理由：短线最怕踩雷，而且利空的规则误判率比利好低（立案、退市这类措辞很固定）。
- 代价：偶尔误杀"利空出尽"的反弹机会；这类机会本来就不在龙头、低吸策略的范围里。
- 改动点：`research_conclusion.build_final_conclusion` 增加一类 blocker；
  `workbench_service` 给候选加 `news` 字段，并在排序时降级。

### C. 消息面加权进评分
- **低吸五维加第六维"消息"**（权重例如 10%）：
  - 利空减分，因为低吸最怕接飞刀；
  - 利好小幅加分。
- **龙头决策**：用消息判断"题材有没有新催化"。
  - 例如龙头当天出了控制权变更或重组，接力周期内可以提高买点信号的可信度；
  - 反过来，龙头出了减持计划或问询函，是退潮信号。
- **利好兑现检查**：利好消息出来时，如果股价已经涨停或累计涨幅超过 X%，就不加分，改为提示"利好可能已兑现"。
- 代价：权重需要回测支撑，否则就是拍脑袋。建议先做下面第 7 节的事件研究，再定权重。

### D. 消息驱动选股（新扫描器）
- 做法：每天盘前，把雷达里的重大利好和显著利好过一遍筛子，列成"消息催化候选"：
  - 能不能买进（用 `buyability`，一字板直接排除）；
  - 题材是否在主线；
  - 当前是哪个情绪周期。
- 适合：重组、控制权变更复牌后的首板或二板接力。
- 代价：要处理停牌、复牌后一字连板等特殊情况，工作量最大。

## 7. 怎么用数据校准权重（学习路线）

现在的等级分和半衰期都是经验值。要让它们有依据，可以做一个小的**事件研究（event study）**：

1. **攒样本**：每天把雷达里的事件存下来，包括代码、类型、反应日。这需要加一张 SQLite 表。
2. **算反应**：对每个事件，计算反应日及之后第 1、3、5 个交易日的超额收益（个股涨幅减去沪深 300）。
3. **按类型汇总**：统计每类事件的平均反应和胜率，看反应随时间怎么衰减。
4. **反推参数**：
   - 平均反应大的事件，调高等级；
   - 反应消失得快的事件，缩短半衰期；
   - 平均反应接近 0 的事件，降为噪音。
5. **放进回测实验室**：做一个"事件类型 × 持有天数"的表，每周自动更新，和现有的周期回测放在一起看。

做完之后，第 6 节 B、C 方案里的权重就有数据支撑，不用拍脑袋。
